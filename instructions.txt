## 📖 What This File Contains

Additional details about the template structure and conventions.

### 1. Initial Setup (Covered in QUICKSTART.md)

1. Clone this template to your new project directory
2. Run `node dev-tools/update-root-mapfile.js` to generate the project map
3. Initialize version control: `git init`
4. Update README.md with your project name

### 2. Working with AI Agents

This template is designed for **AI-assisted development**. You'll use AI agents in different roles:

- **Lead Architect** - Creates Single Source of Truth (SSoT) and system architecture
- **Documentation Specialist** - Generates technical specifications
- **Project Manager** - Creates task lists and timelines
- **QA Engineer** - Designs testing strategies
- **Development Coordinator** - Orchestrates feature implementation
- **DevOps Specialist** - Handles deployment configuration

See WORKFLOW-GUIDE.md for specific prompts for each agent role.

### 3. The AI-Assisted Workflow

Instead of manually setting up everything, you'll use AI agents to:

1. **Generate specifications** from your brainstorming docs
2. **Create architecture** and technical decisions
3. **Build features** following the specifications
4. **Write tests** for quality assurance
5. **Polish documentation** for production readiness

The full process is documented in WORKFLOW-GUIDE.md.

### 4. Mapfile Maintenance

Each directory contains a mapfile.md that tracks:
- Directory purpose and contents
- Work logs and history (AI agents update these)
- Active issues and todos
- Dependencies and processes

**AI agents automatically update mapfiles** when they complete work. You should:
- Review mapfile work logs to see what was done
- Track decisions and blockers manually if needed
- Run `node dev-tools/update-root-mapfile.js` after major milestones to regenerate the project overview

### 5. Documentation (AI-Generated)

AI agents will generate most documentation automatically:
- /docs/API.md - Generated from SSoT by Documentation Specialist
- /docs/AUTH.md - Generated based on architecture decisions
- /docs/SETUP.md - Generated based on tech stack choices
- /docs/DEPLOYMENT.md - Generated by DevOps Specialist

Your job is to **review and refine** what AI generates, not write from scratch.

## Template Conventions

### Directory Ownership

Assign owners to directories by updating the `owner` field in mapfile.md:
- For solo projects: Use your name or "owner"
- For team projects: Use role names ("frontend-dev", "backend-dev") or actual names
- AI agents will reference ownership when updating mapfiles
- Format: "[assign-owner]" → "your-name" or "role-name"

### Status Values

- `template` - Initial state, needs configuration
- `active` - Currently in development
- `stable` - Complete and tested
- `deprecated` - Scheduled for removal

### Work Log Format

```markdown
### [YYYY-MM-DD] Entry Title

- **Developer:** Your Name
- **Task Type:** code | test | doc | refactor | debug
- **Status:** done | in_progress | blocked
- **Time:** X min
- **Files Touched:**
  - path/to/file1
  - path/to/file2
- **Summary:** What you accomplished
- **Blockers:** None | Description
```

## Best Practices

1. **Keep mapfiles current** - Update as you work, not after
2. **Document decisions** - Use logs/decisions/ for Architecture Decision Records
3. **Follow conventions** - See dev-and-design-guides/development-guide.md
4. **Test early** - Set up testing infrastructure before writing features
5. **Iterate on docs** - Empty sections are prompts to fill in later
